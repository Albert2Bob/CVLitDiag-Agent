# 计算机视觉科研问答系统开发计划

## 1. 项目目标

本项目建设一个面向计算机视觉与深度学习研究的科研问答系统。用户可以上传论文、技术文档、实验配置和训练日志，通过多轮对话完成文献问答、论文对比、概念解释、实验诊断和实验方案规划。

系统采用 Vue 3 前端、Python/FastAPI 后端、LangChain Agent 和 DeepSeek 模型。核心能力包括渐进式披露 Skills、多路召回 RAG、MCP Server/Client、Function Calling、结构化输出、短期与长期记忆、上下文组装、SSE 流式交互，以及具备异常恢复和自动评测能力的 Agent Harness。

首个可用版本聚焦以下场景：

1. 针对上传的 CV/DL 论文进行带出处的问答。
2. 对两篇或多篇论文的方法、数据集和实验结果进行比较。
3. 根据训练日志分析过拟合、欠拟合、学习率异常等问题。
4. 根据显存、数据规模和任务目标生成可验证的实验建议。

## 2. 范围边界

首版支持文本型 PDF、Markdown、TXT、CSV 和 JSON。扫描 PDF、复杂公式识别和任意 Python 代码执行不纳入首版。系统可以提出训练实验建议，但不自动启动高成本训练任务。

首版使用单 Agent。检索融合、权限检查、引用校验、日志统计和重试由确定性代码执行，避免把所有控制逻辑交给模型。

## 3. 总体架构

```text

   │ REST：创建任务、上传文件、查询历史
   │ SSE：进度事件、答案增量、完成或失败

   ▼
Agent Harness
   ├── LangChain Agent + DeepSeek
   ├── Prompt / Structured Output
   ├── Skills Registry
   ├── Context Builder
```

## 4. 分阶段开发计划

### 阶段 0：需求、数据契约与工程基础

目标是先固定边界、接口和数据结构，防止后续模块各自定义一套格式。

开发内容：

- 建立后端、前端、Skills、MCP Server、评测和数据目录。
- 确定 Python、Node.js、数据库和依赖版本。
- 配置环境变量读取、日志、异常基类和开发环境。
- 定义 `user_id`、`project_id`、`thread_id`、`run_id`、`document_id` 和 `evidence_id`。
- 设计数据库表和迁移方案，但只实现首版必要字段。
- 准备 10 个固定问题和 3 份小型资料作为冒烟测试集。

验收标准：

- 前后端可以独立启动。
- `/health` 能检查 API、数据库和模型配置状态。
- 所有核心 ID 和状态枚举都有唯一的数据定义。
- 敏感配置仅通过环境变量传入。

### 阶段 1：Vue 前端原型

目标是完成可用于后续联调的交互外壳。

开发内容：

- 登录占位与项目选择页面。
- 对话页面：消息区、输入框、停止按钮、重新生成按钮。
- 文件管理：上传论文或日志、查看解析状态、删除资料。
- 引用面板：显示文档名、页码、证据片段。
- Agent 运行时间线：展示技能加载、检索和工具执行状态。
- Pinia 管理会话、任务状态和当前项目。
- API Client 与 EventSource Client 封装。

验收标准：

- 使用 Mock 数据可以完成发问、流式显示、引用跳转和错误提示。
- 页面刷新后能根据 `run_id` 恢复运行状态。
- 桌面端主要页面无明显布局问题。

### 阶段 2：LangChain Agent、DeepSeek 与 SSE 最小闭环

目标是先跑通一个没有 RAG 和复杂工具的完整问答链路。

开发内容：

- 使用 LangChain 创建单 Agent，并接入 DeepSeek Chat 模型。
- 设计最小系统提示词和用户请求模板。
- 实现运行状态机：`queued → running → completed/failed/cancelled`。
- 提供 `POST /api/runs`、`GET /api/runs/{id}`、`GET /api/runs/{id}/events` 和取消接口。
- SSE 事件至少包括 `run_started`、`answer_delta`、`completed`、`failed` 和 `heartbeat`。
- 为事件分配递增 ID，并支持 `Last-Event-ID` 断线续传。
- 保存最终回答；SSE 重连只回放事件，不能重复运行 Agent。

验收标准：

- 用户提交问题后能持续看到答案增量。
- 断开 SSE 后可以恢复，且不会创建第二次模型调用。
- 可取消尚未完成的运行。
- DeepSeek 超时或拒绝请求时，前端收到明确失败事件。

### 阶段 3：Function Calling 与结构化输出

目标是建立稳定的模型、工具和应用数据契约。

开发内容：

- 使用 Pydantic 定义全部工具入参和返回值。
- 设计统一工具响应：`ok`、`data`、`error`、`trace_id` 和耗时。
- 定义错误码：参数错误、权限错误、超时、限流、服务不可用、结果为空。
- 创建基础工具，例如列出项目文档、读取文档元数据和获取当前时间。
- 定义最终回答模型：回答状态、摘要、结论、引用、假设、建议实验、缺失信息。
- 结构化输出校验失败时，只允许一次定向修复。
- 记录原始工具调用、校验结果和最终标准化结果。

验收标准：

- 非法参数不能进入工具实现。
- 模型无法伪造当前用户无权访问的 `document_id`。
- 最终输出能稳定反序列化，并可直接供前端渲染。
- 重复的只读工具调用可以命中本次运行缓存。

### 阶段 4：文档入库与多路召回 RAG

目标是实现带真实证据和页码的科研问答。

离线入库流程：

```text
上传 → 文件校验 → 文本提取 → 章节识别 → 分块
→ 元数据补全 → Embedding → 向量索引与关键词索引
```

在线召回流程：

```text
问题规范化与中英文术语扩展
→ BM25 关键词召回
→ 向量语义召回
→ 文档摘要召回后进行文档内召回
→ RRF 融合与去重
→ Cross-Encoder 重排
→ 选择证据并补取相邻块
```

开发内容：

- 保存标题、章节、PDF 页码、版本、内容哈希和访问范围。
- 同一问题并行执行三路召回。
- 使用 Reciprocal Rank Fusion 融合排名，不直接相加不同检索器的原始分数。
- 限制单篇论文占用的证据数量，保证论文比较的覆盖面。
- 每条证据分配稳定的 `evidence_id`。
- Agent 最多允许两轮检索，第二轮只能补充明确的信息缺口。
- 回答中的引用必须通过后端验证。

验收标准：

- 文献事实问答能给出文档、页码和证据片段。
- 引用 ID 必须来自当前运行真实返回的证据。
- 在人工标注的小型测试集上统计 Recall@5、Recall@10 和引用支持率。
- 未找到证据时返回 `insufficient_evidence`，而不是编造引用。

### 阶段 5：渐进式披露 Skills 系统

目标是把“如何完成任务”的过程知识从系统提示词中拆出，并只在需要时加载。

每个 Skill 建议采用：

```text
skill-name/
├── SKILL.md              # 元数据、适用条件和核心步骤
├── references/           # 按需读取的详细知识
├── scripts/              # 可控的确定性脚本
└── assets/               # 模板和静态资源
```

首版 Skills：

- `paper-qa`：单篇论文事实解释和引用规则。
- `paper-comparison`：跨论文可比性检查和对比维度。
- `training-diagnosis`：训练曲线诊断和假设验证。
- `experiment-planning`：按成本与信息收益安排实验。

开发内容：

- 启动时只加载所有 Skill 的名称和描述。
- Agent 选中 Skill 后加载完整 `SKILL.md`。
- 只有技能步骤明确需要时，才读取 `references`、`scripts` 或 `assets`。
- 校验 Skill 名称、元数据、相对路径、大小和允许工具。
- 在运行记录中保存 Skill 版本、加载层级和 token 开销。
- 防止 Skill 内容覆盖系统安全规则或读取目录外文件。

验收标准：

- 四类任务的 Skill 选择正确率达到预设目标。
- 未命中的 Skill 正文不会进入模型上下文。
- 与全量加载方案相比，统计输入 token 和响应耗时变化。

### 阶段 6：MCP Server、Client 与 Agent 工具适配

目标是通过标准协议提供可独立运行和测试的科研工具。

开发内容：

- 创建 `cv-research` MCP Server。
- 首版提供 `read_paper_section`、`analyze_training_log` 和 `get_experiment_config`。
- `analyze_training_log` 用确定性代码返回最佳 epoch、训练验证差距、异常值和趋势。
- 开发 MCP Client，完成初始化、能力发现、工具列表获取、调用和关闭。
- 将 MCP Tool 转换为 LangChain Tool，同时保留 JSON Schema。
- 本地开发支持 stdio；服务部署使用 Streamable HTTP。
- 对连接失败、协议错误、工具超时和服务重启进行处理。
- MCP 工具遵守当前用户与项目的资源访问范围。

验收标准：

- 可脱离 Agent 单独测试 MCP Server。
- Agent 可以发现并正确调用三个 MCP 工具。
- MCP Server 不可用时，系统能返回部分结果或清晰的可恢复错误。
- 前端 SSE 能展示 MCP 工具的开始、结束和失败事件。

### 阶段 7：提示词工程与上下文工程

目标是稳定回答行为，并控制长对话的成本与干扰。

提示词分层：

- 系统提示词：角色、证据规则、工具规则、数据边界和停止条件。
- Skill 指令：特定任务的执行步骤、检查表和输出要求。
- 用户提示模板：当前问题、项目范围、输出偏好和约束。
- 工具描述：调用条件、参数语义、返回内容和失败含义。
- 少样本示例：正确引用、证据不足、论文不可直接比较等典型情况。

短期记忆：

- 以 `thread_id` 为隔离单位，用 LangGraph Checkpointer 保存消息、任务状态、已加载 Skill、证据和工具结果。
- 保留最近若干轮完整消息；较早内容压缩为结构化摘要。
- 压缩时保留工具调用与工具结果的完整配对。

长期记忆：

- 用户偏好：语言、回答深度和代码框架偏好。
- 项目事实：任务类型、模型、显存、数据规模和评价指标。
- 已验证经验：实验条件、变化和经过确认的结果。
- 每条记忆记录来源、作用域、创建时间、置信度和失效状态。
- 采用“提取候选 → 价值判断 → 去重/冲突检查 → 写入”的流程。
- 论文知识进入 RAG，不混入用户长期记忆；模型建议不能直接写成已验证经验。

上下文组装顺序：

```text
系统规则
→ 已选 Skill
→ 当前项目相关的长期记忆
→ 较早历史摘要
→ 近期完整消息
→ 当前用户问题
→ 本轮工具结果与证据
```

开发内容：

- 实现 token 预算器，为输出和下一次工具结果预留空间。
- 超出预算时优先移除重复证据、旧工具输出和低相关历史。
- 对长期记忆按作用域、相关性、时效性和可信度排序。
- 对提示词和上下文策略进行版本管理。

验收标准：

- 多轮追问能正确继承当前论文和项目条件。
- 不同项目之间不串用事实记忆。
- 长对话压缩后，关键约束和有效引用仍然保留。
- 能统计每类上下文占用的 token。

### 阶段 8：Agent Harness、可观测性和异常恢复

目标是让 Agent 在模型和外部工具不稳定时仍然可控、可查和可恢复。

开发内容：

- 为每次运行设置总超时、模型调用次数、工具调用次数、检索轮数和 token 预算。
- 只对幂等、可重试错误采用指数退避，并限制最大重试次数。
- 检测同参数重复调用、空结果循环和无进展循环。
- 实现工具级超时、并发限制、熔断和运行取消。
- 对结构化输出、引用、权限范围和最终状态进行统一校验。
- 记录 `trace_id`、提示词版本、模型、Skill 版本、工具耗时、token 和成本。
- 对日志中的 API Key、访问令牌和用户敏感内容脱敏。

建议故障处理矩阵：

| 故障 | 默认处理 |
|---|---|
| 工具参数不合法 | 返回字段级错误，允许 Agent 修正一次 |
| DeepSeek 限流或临时失败 | 有界退避重试，仍失败则结束运行 |
| 检索无结果 | 改写查询一次，再失败则报告证据不足 |
| MCP Server 不可用 | 熔断并使用仍可用的工具返回部分结果 |
| 结构化输出失败 | 按校验错误定向修复一次 |
| 重复工具调用 | 返回缓存结果或终止无进展循环 |
| 超出预算 | 使用已有证据生成部分回答并标明状态 |
| SSE 客户端断线 | Agent 继续执行，事件持久化供重连回放 |

验收标准：

- 每次运行可以通过 `trace_id` 还原主要决策和工具轨迹。
- 注入超时、空检索、非法结构和 MCP 断连后，系统状态仍一致。
- 取消任务后不再产生新的模型或工具调用。

### 阶段 9：评测体系与消融实验

目标是用固定数据证明系统改动是否真正改善质量。

评测集建议包含至少 100 个样例：

- 单篇论文事实问答 30 个。
- 多论文比较 20 个。
- CV/DL 概念与方法解释 15 个。
- 训练日志诊断 20 个。
- 多轮记忆与项目隔离 10 个。
- 工具故障和证据不足 10 个以上。

每个样例保存：问题、允许文档、必要证据、关键答案点、期望工具、禁止结论和评分规则。

核心指标：

| 模块 | 指标 |
|---|---|
| RAG | Recall@K、MRR、重排增益、证据覆盖率 |
| 回答 | 关键点覆盖率、事实正确率、拒答合理性 |
| 引用 | 引用有效率、引用支持率、页码准确率 |
| Skills | 选择正确率、无关加载率、token 开销 |
| 工具 | 工具选择准确率、参数正确率、恢复成功率 |
| 记忆 | 提取准确率、召回准确率、跨项目串用率 |
| 系统 | 完成率、P50/P95 延迟、token 与调用成本 |

消融实验：

1. 单向量召回与三路召回比较。
2. 全量加载 Skills 与渐进式加载比较。
3. 全量历史与“摘要 + 相关记忆”比较。
4. 无 Harness 与有异常恢复机制比较。
5. 无重排与 Cross-Encoder 重排比较。

验收标准：

- 评测命令可以固定模型参数并批量运行测试集。
- 每次评测保存配置、版本、逐题结果和汇总报告。
- 自动指标之外，对内容质量进行人工抽样复核。

### 阶段 10：系统联调、部署与文档

目标是形成可复现部署、可演示和可继续研究的完整项目。

开发内容：

- 使用 Docker Compose 编排 API、Worker、PostgreSQL/pgvector、Redis 和 MCP Server。
- 完成数据库备份、索引重建和数据迁移流程。
- 编写开发部署、生产部署、数据入库、Skill 编写和 MCP 工具开发文档。
- 进行端到端、并发、长连接、权限隔离和故障恢复测试。
- 准备演示数据与演示脚本。

验收标准：

- 新环境按照文档可以独立启动系统。
- 完成“上传论文 → 入库 → 提问 → 调用工具 → 流式回答 → 查看引用”的端到端流程。
- 所有关键服务都有健康检查，失败时不会留下永久运行中的任务。

## 5. API 与 SSE 契约建议

核心 REST API：

```text
POST   /api/projects
POST   /api/projects/{project_id}/documents
GET    /api/documents/{document_id}
DELETE /api/documents/{document_id}
POST   /api/threads
GET    /api/threads/{thread_id}/messages
POST   /api/runs
GET    /api/runs/{run_id}
POST   /api/runs/{run_id}/cancel
GET    /api/runs/{run_id}/events
```

核心 SSE 事件：

```text
run_started
skill_selected
skill_loaded
retrieval_started
retrieval_finished
tool_started
tool_finished
answer_delta
validation_failed
completed
failed
cancelled
heartbeat
```

事件公共字段建议包含：`event_id`、`run_id`、`sequence`、`timestamp`、`type` 和 `payload`。前端只把 `completed` 事件内经过校验的回答作为最终结果。

## 6. 关键数据模型

最终回答至少包含：

```text
status: complete | partial | insufficient_evidence
summary: string
claims[]:
  - statement
  - evidence_ids[]
hypotheses[]:
  - hypothesis
  - confidence
  - validation_method
experiments[]:
  - objective
```

## 7. 推荐开发顺序与时间估算

按一名具备 Python 和基础前端能力的研究生估算：

| 第 3 周 | 阶段 2 | DeepSeek + Agent + SSE 最小闭环 |
| 第 4 周 | 阶段 3 | 工具调用和结构化输出 |

## 8. 阶段依赖与完成定义

阶段 0～3 构成最小问答底座；阶段 4 让答案具备文献依据；阶段 5～7提供任务流程、外部工具和连续对话能力；阶段 8～10让系统可测试、可恢复和可部署。

每个阶段只有同时满足以下条件才算完成：

1. 功能达到该阶段验收标准。
2. 关键路径有自动测试或固定的可复现实验。
3. 接口、数据格式和环境变量已经记录。
4. 失败路径已验证，不会只处理理想输入。
5. 新增能力已纳入运行日志和评测范围。

## 9. 主要风险与控制方式

- DeepSeek Function Calling 或结构化输出存在模型差异：用 Pydantic 校验和一次修复兜底，并先用小型契约测试验证所选模型。
- PDF 提取质量影响引用：记录解析质量，保留页码映射，对扫描文档明确提示暂不支持。
- 中英文跨语言检索不稳定：保留原查询，同时扩展英文术语，并用固定测试集调整权重。
- 长期记忆污染：只有明确、稳定、可复用的信息才能写入，并保留来源与作用域。
- Agent 无限循环或成本失控：在 Harness 中硬性限制调用次数、总耗时、检索轮数和 token。
- SSE 经代理缓冲或断线：关闭不适合的响应缓冲，发送心跳，持久化事件并支持续传。
- 评测被提示词过拟合：分离开发集与测试集，测试集只用于阶段性评估。

## 10. 推荐里程碑

- M1：可以通过网页与 DeepSeek 流式对话。
- M2：可以调用类型安全的本地工具并返回结构化结果。
- M3：可以对上传论文进行多路检索和真实引用。
- M4：可以按需加载四种 Skills，并调用 MCP 日志分析工具。
- M5：具备长短期记忆、上下文预算和异常恢复。
- M6：完成固定评测集、消融实验和可复现部署。
